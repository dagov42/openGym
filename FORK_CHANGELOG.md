Этот файл ведётся только в форке [dagov42/openGym](https://github.com/dagov42/openGym).
Здесь фиксируется всё, что приходит из апстрима [DuarteSantos8/openGym](https://github.com/DuarteSantos8/openGym)
и что исправляется локально: что за баг, как проявлялся, чем починен и где лежит.

Формат записи:

```

### Причина / что было сломано
### Исправление
### Ссылки (PR / issue / коммиты)
### Проверка (тесты, сборка)
```

План фич и порядок: [FORK_ROADMAP.md](FORK_ROADMAP.md). Схема версий форка:
[FORK_VERSIONING.md](FORK_VERSIONING.md).

## 2026-11-17 — 1.4.8.1: кнопка проверки обновлений

Релиз `v1.4.8.1` (без префикса `fork-`), PR форка [#1](https://github.com/dagov42/openGym/pull/1).

### Причина

- Кнопка «Проверить обновления» не ходила в сеть: `checkForUpdate()` кэширует ответ на всю
  сессию (`maxAge = Infinity` по умолчанию), и открытие About, и сама кнопка переиспользовали
  кэш. Он заполнился до публикации 1.4.8, когда `/releases/latest` был `v1.4.6`.
- `compareSemver` читал только три числа, поэтому `1.4.8.1` не отличался от `1.4.8` и не
  предлагался как обновление.

### Исправление

- `Settings.jsx`: `checkNow()` вызывает `resetUpdateCheck()` перед `checkForUpdate()`, так что
  тап по строке действительно опрашивает GitHub.
- `update.js`: `compareSemver` сравнивает все присутствующие компоненты, включая четвёртый.
- Версия `1.4.8.1` в frontend/api (package.json и lock-файлы) и Android (`versionCode 50`);
  iOS `MARKETING_VERSION` и Garmin остаются `1.4.8` (3 части), iOS build `75`.

### Проверка

- `update.test.js` (сравнение 4 частей) и `Settings.update.test.jsx` (кнопка сбрасывает кэш) —
  зелёные.
- `release-check` для `v1.4.8.1`: frontend/api/Android совпадают, iOS/Garmin — warning.
- Тег `v1.4.8.1`; GitHub release `v1.4.8.1` опубликован. APK/AAB ещё не загружены, `Release
  files` красный до `scripts/android/upload-release.sh v1.4.8.1 <out>`.

## 2026-11-17 — четыре фикса и тестовая гигиена на Windows

Ветка `integration`, PR форка: [#1](https://github.com/dagov42/openGym/pull/1).
Коммиты: `c1d03bee9` (гигиена тестов), `e7879871b` (Coach), `1302639e8` (media),
`ff80dd325` (assisted), `37b902a4b` (log-workout), `c21149be6` (release 1.4.8).

Релиз: версия **1.4.8** во всех местах, тег `fork-v1.4.8` на `c21149be6`; `tests-ok` и
Release check зелёные. GitHub release `v1.4.8 (fork)` опубликован с notes из `CHANGELOG.md`.
Ассеты ещё не загружены: `Release files` красный, APK/AAB нужно собрать на релизной машине и
залить `scripts/android/upload-release.sh fork-v1.4.8 <out>`; после этого проверка станет
зелёной.

Форк развивается самостоятельно: PR в апстрим отдельно не ведутся (открытые пробные
PR #1339–#1342 закрыты), все фиксы остаются в `integration`.

### Причина / что было сломано

- **Windows-тесты.** Оболочка экспортирует `NODE_ENV=production`, из-за чего React не
  отдаёт `act`, `import.meta.env.DEV` ложен, а `import('node:fs')` в happy-dom падает с
  `No such built-in module: node:`. Плюс устаревший CRLF-чекаут ломал сверки «байт в байт»,
  а проверки путей/POSIX-прав падали на Windows.
- **Coach (#1290).** Повтор запроса после обрыва срабатывал только до получения ответа;
  если соединение рвалось при чтении, когда ещё ничего не пришло (`got === 0`), job падал
  без повтора.
- **HEIC (#1268).** Бренды `avci`/`hevc` и бренды в верхнем регистре не распознавались, а
  `avci` подменялся на `image/avif`.
- **Assisted (#1222).** `build.mjs` терял поле `assisted`, поэтому `isAssisted('3235')`
  (cable assisted inverse leg curl, оборудование `cable`) возвращал `false`.
- **log_workout.** Reps-запись сохранялась без явного `mode`, и после переклассификации
  упражнения в cardio (скакалка, #1296) старые reps-строки читались как cardio с нулём минут.

### Исправление

1. `NODE_ENV=test` выставляется до разрешения Vite-конфига (`VITEST`), пути сравниваются
   как POSIX, POSIX-права проверяются под `win32`-гардом, а тесты, которым нужен POSIX или
   `sh`, помечены `skipIf(win32)` с комментарием. Политика LF — в `.gitattributes`.
   Подробности и список скипов: `docs/dev/WINDOWS_TESTS.md`.
2. Ретрай вынесен в общий `retryAfterDrop`: второй catch при `got === 0` делает тот же
   единственный повтор, бюджет и дедлайн общие (повтор получает остаток таймаута).
3. Полный список брендов ISO/IEC 23008-12, HEIF сравнивается без учёта регистра,
   `avci` → `image/avci`.
4. `build.mjs` пишет `assisted: 1`, `assistedShape` доверяет явному флагу, `3235.json`
   получил `"assisted": true`, `exercises-data.js` пересобран.
5. `log-workout.js` пишет `mode: 'reps'` рядом с уже существующим `mode: 'time'`.

### Проверка (CI и локально)

- Локально: frontend — 10 237 тестов, 0 стабильных падений, 11 skip (1 известный флейк
  `GymReminder` под нагрузкой); api — 1 100 тестов, 0 падений, 5 skip; mcp — 172 теста,
  0 падений, 1 skip. Целевые тесты четырёх фиксов: 422 frontend + 65 api — зелёные.
  `node scripts/catalogue/build.mjs --check` — up to date.
- CI GitHub Actions на `37b902a4b`: `frontend`, `api`, `mcp`, `catalogue`, `images`,
  `report`, `tests-ok`, `gate`, `changes` — success; `cla` — failure (бот CLA в форке не
  валидирует коммиты); android/routines/device-archive/simulator/ui-tests — skipped.

## 2026-11-16 — исправления критичных issue

### #1296 — скакалка не считалась кардио

**Причина.** У rope-упражнений в каталоге `bodyPart: "full body"`, а `isCardio`
проверял только `bp === 'cardio'`. Поэтому `log_workout` отклонял минуты
(«this one takes reps or seconds»), а недельный cardio total игнорировал
записанные секунды.

**Исправление.** Восемь rope-упражнений переведены на `bodyPart: "cardio"`:
`2612`, `3675`, `3676`, `3677`, `3678`, `3885`, `4829`, `5038`. Пересобраны
`exercises-data.js`, coach library и browse-страницы каталога. `6100`
(bodyweight skipping, без скакалки) остался сетами/повторами.
`cardio-reps.test.js` обновлён под новое поведение.

**Заодно.** `scripts/catalogue/validate.mjs` теперь знает поле `assisted`
(появилось в #1222, из-за него `build.mjs --check` падал на `3235.json`).

### #1268 — iPhone отклонял фото из библиотеки

**Причина.** `sniffKind` узнавал только часть HEIF-брендов. 10-битный HEIC
(`heix`), HEVC-последовательности (`hevx`, `hevm`, `hevs`), `mif2`, `avci`
и бренды в верхнем регистре возвращали `null`, и `ingestMediaFile` кидал
`MediaError('type')`. Тот же код используется аватаром.

**Исправление.** Полный список брендов ISO/IEC 23008-12 плюс `avci`, а HEIF
сравнивается без учёта регистра. Тест добавлен в `media-sniff.test.js`.

**Ограничение.** DNG/ProRAW браузер по-прежнему декодировать не умеет: такой
файл даст «unreadable», а не «type». Для обычных HEIC/AVIF из фотоальбома
путь открыт.

### #1290 — Coach обрывал соединение при уходе в фон

**Причина.** Транспортная ошибка при долгом ожидании ответа провайдера
(`Software caused connection abort` после ~63 с) сразу завершала job, хотя
запрос мог быть оборван транзиентно (смена сети, NAT, уход приложения в фон).

**Исправление.** Один повтор запроса, если соединение оборвалось после ≥ 5 с
ожидания и job не отменён. Мгновенные отказы (DNS, unreachable) не ретраятся,
чтобы не удваивать ожидание. Тесты в `api/test/adapters-http.test.js`.

### #1251 — ChatGPT-коннектор отклонялся

**Причина.** CIMD-документ ChatGPT объявляет
`token_endpoint_auth_method: "private_key_jwt"`, но перечисляет `none` в
`token_endpoint_auth_methods_supported`. Сервер принимал только `none`.

**Исправление.** Публичным считается клиент, у которого declared `none` **или**
`none` есть в списке поддерживаемых методов. Клиент только с `private_key_jwt`
по-прежнему отклоняется.

### #1297 — Gemini не регистрировался (DCR)

**Причина.** `registerClient()` ограничивал `redirect_uris` пятью адресами,
а Google присылает шесть (по одному на surface).

**Исправление.** Лимит поднят до 10, как у client metadata document; сообщение
об ошибке обновлено.
